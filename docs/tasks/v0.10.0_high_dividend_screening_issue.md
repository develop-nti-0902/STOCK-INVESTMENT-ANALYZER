### Issue 2: `SimpleScreeningService` 実装

**ラベル**: `type: feature, layer: service, priority: high, ms: v0.10.0`

#### 概要
`FinancialQueryService` を使って必須条件チェック・スコア計算・ステータス判定を行い、結果をターミナルに出力するサービスを実装する。DB保存・ORM依存なし。

#### 実装ファイル
- `app/services/screening/__init__.py`
- `app/services/screening/simple_screening_service.py`（`ScreeningResult` dataclassを同ファイル内に定義）
- `tests/unit/services/screening/test_simple_screening_service.py`

#### dataclass定義（同ファイル内）
`ScreeningResult`: `sec_code`, `pass_required`, `total_score`, `score_dividend`, `score_eps`, `score_stability`, `score_profitability`, `status`, `failed_conditions`

#### 公開メソッド実装
- `run(sec_codes, evaluation_date) -> None`: 複数銘柄をスクリーニングしてターミナルに出力
- `evaluate(sec_code, evaluation_date) -> ScreeningResult`: 単一銘柄を評価して結果を返す

#### 必須条件チェック（privateメソッド）

| メソッド | 内容 |
|---|---|
| `_check_dividend_continuity` | 減配回数 ≤ 2回 かつ 過去5年内の任意の2年連続減配なし |
| `_check_eps_health` | 赤字EPS（≤ 0）なし かつ 過去5年内の任意の2年連続減少なし かつ 直近1年減少率 < 30% |
| `_check_operating_cf` | 4年以上プラス |

#### スコア計算（privateメソッド）

| メソッド | 配点 | 加点条件（各+10点） |
|---|---|---|
| `_score_dividend` | 0〜30点 | 増配年 ≥ 3年 / 過去5年で2年以上連続増配の期間あり / Kendall τ > 0.4 |
| `_score_eps` | 0〜30点 | EPS増加年 ≥ 3年 / 過去5年で2年以上連続EPS増加の期間あり / Kendall τ > 0.4 |
| `_score_stability` | 0〜20点 | 売上増加年 ≥ 3年 / 営業利益増加年 ≥ 3年 |
| `_score_profitability` | 0〜20点 | 前年差マイナス ≤ 2回 / 2.0pt以上の低下が2年連続なし |

#### ステータス判定

| 条件 | ステータス |
|---|---|
| 必須条件NG | `not_eligible` |
| 必須条件OK かつスコア ≥ 90点 | `priority`（優先購入候補） |
| 必須条件OK かつスコア ≥ 80点 | `active`（積極的に検討） |
| 必須条件OK かつスコア ≥ 70点 | `watch`（監視対象） |
| 必須条件OK かつスコア < 70点 | `not_eligible` |

#### ターミナル出力イメージ
```
[2026-02-18] スクリーニング結果
通過銘柄: 7203, 6758, 4502
---
7203: スコア92 (priority) - 配当30/EPS30/安定20/収益12
6758: スコア82 (active)   - 配当20/EPS30/安定20/収益12
4502: スコア72 (watch)    - 配当20/EPS22/安定20/収益10
不合格: 9999 (eps_health, operating_cf)
```

#### その他
- `_kendall_tau(values) -> float`: `scipy.stats.kendalltau` を使用（`poetry add scipy` が前提）
- `_resolve_status(pass_required, total_score) -> str`

#### テスト
- 必須条件チェック（境界値含む）のユニットテスト
- スコア計算（各軸独立）のユニットテスト
- `run()` のターミナル出力検証（`capsys` 使用）
- `FinancialQueryService` はモック化

#### 完了条件
- `run()` でターミナルにスクリーニング結果（銘柄コード・スコア）が出力される
- ユニットテストがCIで成功する
- `poetry add scipy` 済み
