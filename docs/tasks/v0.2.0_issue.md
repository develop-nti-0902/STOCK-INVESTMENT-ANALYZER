## 概要
ローカル環境にPostgreSQL 14以上をインストールし、プロジェクト用データベースとユーザーを作成します。
**既存の `scripts/databaseSetup/` にあるセットアップスクリプトが実装済みです。残りは設定ファイルとドキュメント整備です。**

## 作業種別

## 作業内容
- PostgreSQL 14以上のローカルインストール確認
  - Windows: 公式インストーラまたはwinget/choco
  - macOS: Homebrew
  - Linux: apt/yum等のパッケージマネージャ
- 環境変数設定（`.env`ファイル）
  ```.env
  PGHOST=localhost
  PGPORT=5432
  PGUSER=postgres
  PGPASSWORD=<postgres_user_password>
  NEW_DB=stock_investment_db
  NEW_DB_USER=stock_user
  NEW_DB_PASSWORD=<new_password>
  DATABASE_URL=postgresql+asyncpg://stock_user:<password>@localhost:5432/stock_investment_db
  ```
- `.env.example` にDB接続情報テンプレートを追加
- データベース作成スクリプト実行
  - Windows: `scripts\databaseSetup\setup_db.bat`
  - Linux/macOS: `scripts/databaseSetup/setup_db.sh`
  - スクリプトは以下を自動実行:
    - データベース作成（`stock_investment_db`）
    - ユーザー作成（`stock_user`）
    - スキーマ適用（`sql/create_stock_tables.sql`, `sql/create_management_tables.sql`）
- 接続確認
  - psqlコマンドでの接続テスト
  - Python経由での接続テスト（psycopg/asyncpg）
- セットアップドキュメント更新
  - `docs/setup/SETUP.md` にPostgreSQLインストール手順追加
  - セットアップスクリプト使用方法の記載

## 理由
Docker不要で、シンプルなローカルPostgreSQL環境を構築し、開発を迅速に開始できるようにします。

## 詳細

### 実装内容

#### 1. ベースモデル定義 (`app/models/base.py`)
- `Base` クラス定義（`DeclarativeBase`）
- 共通カラム定義
  - `id`: 主キー（UUID or SERIAL）
  - `created_at`: 作成日時（デフォルト: now()）
  - `updated_at`: 更新日時（自動更新）
- テーブル命名規則の設定

#### 2. 銘柄マスタモデル (`app/models/stock_master.py`)
- `StockMaster` モデル定義
- カラム:
  - `symbol`: 銘柄コード（Primary Key, VARCHAR(10)）
  - `name`: 銘柄名（VARCHAR(100)）
  - `market`: 市場区分（VARCHAR(50)）
  - `sector`: 業種（VARCHAR(100)）
  - `is_active`: アクティブフラグ（BOOLEAN, デフォルト: true）
  - `listed_date`: 上場日（DATE, NULL許可）
  - `delisted_date`: 上場廃止日（DATE, NULL許可）
  - `created_at`, `updated_at`
- インデックス:
  - `symbol` (Primary Key)
  - `market`, `sector` (検索用)
  - `is_active` (検索用)

#### 3. 株価データモデル（8種類）
以下のモデルを実装（構造は共通、テーブル名のみ異なる）:
- `app/models/stock_data.py`
  - `Stocks1m` (1分足)
  - `Stocks5m` (5分足)
  - `Stocks15m` (15分足)
  - `Stocks30m` (30分足)
  - `Stocks1h` (1時間足)
  - `Stocks1d` (日足)
  - `Stocks1wk` (週足)
  - `Stocks1mo` (月足)

共通カラム:
- `id`: SERIAL (Primary Key)
- `symbol`: VARCHAR(10) (Foreign Key: stock_master.symbol)
- `timestamp`: TIMESTAMP WITH TIME ZONE
- `open`: NUMERIC(12, 2)
- `high`: NUMERIC(12, 2)
- `low`: NUMERIC(12, 2)
- `close`: NUMERIC(12, 2)
- `volume`: BIGINT
- `created_at`: TIMESTAMP WITH TIME ZONE

複合インデックス:
- `(symbol, timestamp)` - UNIQUE制約
- `timestamp` - 時系列検索用

#### 4. バッチ実行履歴モデル (`app/models/batch_execution.py`)
- `BatchExecution` モデル定義
- カラム:
  - `id`: UUID (Primary Key)
  - `job_type`: VARCHAR(50) - バッチ種別
  - `status`: VARCHAR(20) - 実行ステータス（pending/running/success/failed）
  - `started_at`: TIMESTAMP WITH TIME ZONE
  - `completed_at`: TIMESTAMP WITH TIME ZONE (NULL許可)
  - `total_count`: INTEGER - 処理対象数
  - `success_count`: INTEGER - 成功数
  - `failed_count`: INTEGER - 失敗数
  - `error_message`: TEXT (NULL許可)
  - `created_at`, `updated_at`
- インデックス:
  - `job_type`, `status` (検索用)
  - `started_at` (時系列検索用)

#### 5. モデルエクスポート (`app/models/__init__.py`)
- 全モデルのインポート・エクスポート
- `Base.metadata` のエクスポート

### 影響範囲

```markdown

---

## 概要
v0.1.0で定義した抽象インターフェースを実装し、具体的なRepository基底クラスを作成します。

## 詳細

### 実装内容

#### 1. Repository基底クラス実装 (`app/repositories/base.py`)
以下のメソッドを実装:
- `__init__(session)`: セッション受け取り
- `async get(id) -> Optional[Model]`: IDで単一取得
- `async get_multi(skip=0, limit=100) -> List[Model]`: ページネーション付き複数取得
- `async create(data: dict) -> Model`: 新規作成
- `async update(id, data: dict) -> Optional[Model]`: 更新
- `async delete(id) -> bool`: 削除
- `async count() -> int`: 件数取得
- `async exists(id) -> bool`: 存在確認

共通機能:
- トランザクション管理（自動コミット/ロールバック）
- エラーハンドリング
- ロギング
- Generic型による型安全性

#### 2. StockMasterRepository実装 (`app/repositories/stock_master_repository.py`)
`BaseRepository` を継承し、銘柄マスタ固有の操作を追加:
- `async get_by_symbol(symbol: str) -> Optional[StockMaster]`: 銘柄コードで取得
- `async get_by_market(market: str) -> List[StockMaster]`: 市場別取得
- `async search(query: str) -> List[StockMaster]`: 部分一致検索
- `async bulk_create(data_list: List[dict]) -> List[StockMaster]`: 一括作成
- `async upsert(data: dict) -> StockMaster`: UPSERT処理

#### 3. BatchExecutionRepository実装 (`app/repositories/batch_execution_repository.py`)
バッチ実行履歴の操作:
- `async create_job(job_type: str) -> BatchExecution`: ジョブ作成
- `async update_status(id, status: str)`: ステータス更新
- `async mark_completed(id, success_count, failed_count)`: 完了マーク
- `async get_by_job_type(job_type: str) -> List[BatchExecution]`: ジョブ種別で取得
- `async get_recent(limit: int) -> List[BatchExecution]`: 最近の実行履歴

#### 4. 依存性注入の実装
- `app/dependencies.py` にRepository取得関数追加
- FastAPIの依存性注入で使用
- 例:
  ```python
  def get_stock_master_repository(
      session: AsyncSession = Depends(get_db)
  ) -> StockMasterRepository:
      return StockMasterRepository(session)
  ```

### 影響範囲
- `app/repositories/base.py`（実装を追加）

- Generic型 `TypeVar` で型安全性を確保
- SQLAlchemy 2.0の`select()`, `insert()`, `update()`, `delete()`を使用
- 非同期処理（async/await）
- トランザクション境界の明確化
