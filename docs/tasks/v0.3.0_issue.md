### 2. [FEATURE] 株価データ保存Repository実装（UPSERT対応）

```markdown
---

## 概要
取得した株価データをPostgreSQLに保存するRepository層とSaver層を実装し、UPSERT処理で重複を回避します。

## 詳細

### 実装内容

#### 1. 共通保存基盤 (`app/services/core/savers/`)
- `base_saver.py`: データ保存抽象基底クラス
  - `async save_single()`: 単一データ保存
  - `async save_bulk()`: 一括保存
  - トランザクション管理
- `bulk_saver_mixin.py`: 一括保存共通ロジック
  - バッチ処理（チャンク分割）
  - 進捗トラッキング

#### 2. 株価データRepository (`app/repositories/stock_data_repository.py`)
- 8種類のタイムフレーム対応Repository
- `StockDataRepository` 基底クラス
  - `async upsert_single(data)`: 単一データUPSERT
  - `async upsert_bulk(data_list)`: 一括UPSERT
  - `async get_by_symbol_and_range(symbol, start, end)`: 期間指定取得
  - `async get_latest(symbol, limit)`: 最新データ取得
- 具体クラス（8種類）:
  - `StockData1mRepository`
  - `StockData5mRepository`
  - `StockData15mRepository`
  - `StockData30mRepository`
  - `StockData1hRepository`
  - `StockData1dRepository`
  - `StockData1wkRepository`
  - `StockData1moRepository`

#### 3. 株価データSaver (`app/services/market_data/stock_price/saver.py`)
- `StockPriceSaver` クラス実装
- メソッド:
  - `async save_stock_data(symbol, timeframe, data)`: データ保存オーケストレーション
  - `async save_multiple_stocks(data_dict)`: 複数銘柄一括保存
  - `_select_repository(timeframe)`: タイムフレーム別Repository選択
  - `_prepare_data_for_db(df)`: DataFrameからDB形式への変換

#### 4. UPSERT処理実装
- PostgreSQLの`ON CONFLICT`句を使用
- 複合ユニークキー: `(symbol, timestamp)`
- コンフリクト時の更新戦略:
  - open, high, low, close, volume を更新
  - created_at は保持、updated_at のみ更新

#### 5. トランザクション管理
- 一括保存時のトランザクション境界
- エラー時のロールバック
- コミット/ロールバックのロギング

### 影響範囲
- `app/services/core/savers/`（新規作成）
- `app/repositories/stock_data_repository.py`（新規作成）
- `app/services/market_data/stock_price/saver.py`（新規作成）

### 技術的な考慮事項
- SQLAlchemy 2.0のUPSERT構文（`insert().on_conflict_do_update()`）
- 非同期バッチ処理のパフォーマンス最適化
- トランザクション分離レベルの設定
- メモリ効率を考慮したチャンク処理

### 3. [FEATURE] 株価データ収集サービス実装（オーケストレーション）

```markdown

labels: 'type: feature, status: todo, ms: v0.3.0, layer: service'

milestone: v0.3.0
---

## 概要
データ取得（Fetcher）と保存（Saver）を統合し、株価データ収集の全体フローを管理するサービスを実装します。

## 詳細

### 実装内容

#### 1. データ変換層 (`app/services/market_data/stock_price/converter.py`)
- `StockPriceConverter` クラス実装
- メソッド:
  - `async yfinance_to_pydantic(df, symbol, timeframe)`: yfinance DataFrame → Pydantic
  - `async pydantic_to_dict(stock_data)`: Pydantic → Dict（DB保存用）
  - `_validate_data(df)`: データ検証
  - `_normalize_timestamps(df)`: タイムスタンプ正規化

#### 2. データ検証層 (`app/services/market_data/stock_price/validator.py`)
- `StockPriceValidator` クラス実装
- 検証項目:
  - 必須カラムの存在確認（open, high, low, close, volume）
  - 数値範囲の検証（価格が負でない、volumeが0以上）
  - OHLC整合性チェック（high >= open/close/low, low <= open/close/high）
  - 欠損値の処理方針
  - タイムスタンプの妥当性検証

#### 3. 株価データサービス (`app/services/market_data/stock_price/service.py`)
- `StockPriceService` クラス実装（オーケストレーション層）
- メソッド:
  - `async fetch_and_save_single(symbol, timeframe, start_date, end_date)`: 単一銘柄
    1. Fetcherでデータ取得
    2. Converterでデータ変換
    3. Validatorで検証
    4. Saverで保存
    5. 結果を返却
  - `async fetch_and_save_multiple(symbols, timeframe, start_date, end_date)`: 複数銘柄並列処理
    1. 並列度制御（セマフォ）
    2. 各銘柄を並列取得・保存
    3. 進捗トラッキング
    4. エラー集約
  - `async get_stock_data(symbol, timeframe, start_date, end_date)`: データ取得（読み取り専用）
- 依存性注入:
  - `StockPriceFetcher`
  - `StockPriceSaver`
  - `StockPriceConverter`
  - `StockPriceValidator`

#### 4. Pydanticスキーマ定義 (`app/schemas/stock_data.py`)
- `StockPriceBase`: 基底スキーマ
- `StockPriceCreate`: 作成用スキーマ
- `StockPriceResponse`: レスポンス用スキーマ
- `StockPriceBatch`: バッチ処理用スキーマ
- タイムフレーム別スキーマ（必要に応じて）

### 影響範囲
- `app/services/market_data/stock_price/converter.py`（新規作成）
- `app/services/market_data/stock_price/validator.py`（新規作成）
- `app/services/market_data/stock_price/service.py`（新規作成）
- `app/schemas/stock_data.py`（新規作成）

### 技術的な考慮事項
- asyncio.gather()による並列処理
- asyncio.Semaphoreによる並列度制御
- エラー発生時も他の銘柄処理を継続
- 進捗トラッキングと部分的成功の管理

### 5. [FEATURE] バッチ実行履歴管理機能実装

```markdown
---
name: 機能追加
about: バッチ処理の実行履歴を記録・管理する機能実装
title: '[FEATURE] バッチ実行履歴管理機能実装'
labels: 'type: feature, status: todo, ms: v0.3.0, layer: service, layer: repository'
assignees: ''
milestone: v0.3.0
---

## 概要
データ収集バッチの実行履歴をDBに記録し、ステータス管理・エラートラッキング機能を実装します。

## 詳細

### 実装内容

#### 1. バッチ実行管理サービス (`app/services/batch/batch_execution_service.py`)
- `BatchExecutionService` クラス実装
- メソッド:
  - `async create_job(job_type, params) -> BatchExecution`: ジョブ作成
  - `async start_job(job_id)`: ジョブ開始
  - `async update_progress(job_id, progress)`: 進捗更新
  - `async complete_job(job_id, success_count, failed_count)`: ジョブ完了
  - `async fail_job(job_id, error_message)`: ジョブ失敗
  - `async get_job_status(job_id) -> BatchExecution`: ステータス取得
  - `async get_recent_jobs(limit=10) -> List[BatchExecution]`: 最近の実行履歴
  - `async get_jobs_by_type(job_type) -> List[BatchExecution]`: タイプ別履歴

#### 2. バッチ実行コンテキストマネージャー
- `BatchExecutionContext` クラス
- 使用例:
  ```python
  async with BatchExecutionContext(
      batch_service,
      job_type="jpx_stock_data",
      params={"timeframe": "1d"}
  ) as ctx:
      # バッチ処理
      result = await process_batch()
      ctx.update_progress(processed=100, total=4000)
  # 自動的にステータス更新（成功/失敗）
  ```

#### 3. ジョブタイプ定義 (`app/schemas/batch.py`)
- `JobType` Enum:
  - `SINGLE_STOCK`: 単一銘柄データ取得
  - `JPX_ALL_STOCKS`: JPX全銘柄データ取得
  - `STOCK_MASTER_UPDATE`: 銘柄マスタ更新
  - `FUNDAMENTAL_DATA`: ファンダメンタルデータ取得
- `JobStatus` Enum:
  - `PENDING`: 待機中
  - `RUNNING`: 実行中
  - `COMPLETED`: 完了
  - `FAILED`: 失敗
  - `CANCELLED`: キャンセル

#### 4. Pydanticスキーマ (`app/schemas/batch.py`)
- `BatchExecutionBase`: 基底スキーマ
- `BatchExecutionCreate`: 作成用
- `BatchExecutionUpdate`: 更新用
- `BatchExecutionResponse`: レスポンス用
- `BatchJobParams`: パラメータスキーマ

#### 5. Repository拡張 (`app/repositories/batch_execution_repository.py`)
- v0.2.0で作成した基礎から拡張
- メソッド追加:
  - `async update_progress(job_id, progress_data)`: 進捗更新
  - `async get_running_jobs() -> List[BatchExecution]`: 実行中ジョブ取得
  - `async cancel_job(job_id)`: ジョブキャンセル

#### 6. 株価データサービスへの統合
- `StockPriceService` にバッチ履歴記録を統合
- 各メソッドでBatchExecutionContextを使用
- エラー時の自動記録

## 詳細

### 実装内容

#### 1. バッチAPIルーター (`app/api/v1/batch.py`)
エンドポイント実装:

##### `POST /api/v1/batch/stock-data/single`
- 単一銘柄のデータ取得
- リクエストボディ:
  ```json
  {
    "symbol": "7203",
    "timeframe": "1d",
    "start_date": "2024-01-01",
    "end_date": "2024-12-31"
  }
  ```
- レスポンス: ジョブID + ステータス

##### `POST /api/v1/batch/stock-data/jpx-all`
- JPX全銘柄の一括取得
- リクエストボディ:
  ```json
  {
    "timeframe": "1d",
    "start_date": "2024-01-01",
    "end_date": "2024-12-31",
    "market": "プライム"  // オプション
  }
  ```
- レスポンス: ジョブID + 推定処理時間
- 非同期処理（バックグラウンドタスク）

##### `GET /api/v1/batch/status/{job_id}`
- ジョブステータス取得
- レスポンス:
  ```json
  {
    "job_id": "uuid",
    "job_type": "jpx_all_stocks",
    "status": "running",
    "progress": {
      "processed": 1500,
      "total": 4000,
      "percentage": 37.5
    },
    "started_at": "2024-11-28T10:00:00Z",
    "estimated_completion": "2024-11-28T10:30:00Z"
  }
  ```

##### `GET /api/v1/batch/history`
- 実行履歴一覧取得
- クエリパラメータ:
  - `job_type`: ジョブタイプフィルタ
  - `status`: ステータスフィルタ
  - `limit`: 取得件数（デフォルト10）

##### `DELETE /api/v1/batch/cancel/{job_id}`
- 実行中ジョブのキャンセル

#### 2. 株価データAPIルーター (`app/api/v1/stock_data.py`)
エンドポイント実装:

##### `GET /api/v1/stock-data/{symbol}`
- 銘柄の株価データ取得（読み取り専用）
- クエリパラメータ:
  - `timeframe`: タイムフレーム
  - `start_date`: 開始日
  - `end_date`: 終了日
  - `limit`: 取得件数

#### 3. 依存性注入設定 (`app/dependencies.py`)
- `get_stock_price_service()`: StockPriceService取得
- `get_batch_execution_service()`: BatchExecutionService取得
- セッション管理

#### 4. バックグラウンドタスク実装
- FastAPIのBackgroundTasksを使用
- 長時間実行タスクの非同期処理
- タスク実行中のステータス更新

#### 5. エラーハンドリング
- カスタム例外クラスのHTTPレスポンス変換
- 適切なHTTPステータスコード
- エラーメッセージの統一フォーマット

#### 6. API統合 (`app/api/v1/__init__.py`)
- ルーター登録
- API v1の構成
