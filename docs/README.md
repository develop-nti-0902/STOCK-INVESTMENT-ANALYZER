## 概要

- **目的**
	- このフォルダはプロジェクト全体のドキュメントを体系的に集約します。アーキテクチャ設計、開発ガイドライン、フロントエンド仕様、タスク管理規約など、プロジェクトに関するあらゆる情報を一元管理します。

- **利用方法**
	- 新規メンバーのオンボーディング、設計確認、開発作業、コードレビュー時に参照してください。各ディレクトリの `README.md` から必要な情報にアクセスできます。

## 重要な注意

設計書（architecture/, develop-guide/, frontend/ など）は、**設計思想と方向性を示すドキュメント**です。具体的な実装コードや詳細な設計仕様は掲載されていません。これらを参考にする際は、実装コードも合わせて確認してください。

## ディレクトリ構成

### architecture/
システムのアーキテクチャ設計に関するドキュメント群です。

- **概要**: 全体のアーキテクチャ方針、レイヤ構成、各層の責務と設計原則を定義します。
- **注意**: 設計思想と方向性を示すドキュメントであり、具体的な実装フローや詳細仕様は掲載されていません。
- **主な内容**:
  - アーキテクチャ全体概要
  - レイヤ別詳細設計（API層、サービス層、データアクセス層、データストレージ層、プレゼンテーション層、共通モジュール）
- **詳細**: [architecture/README.md](architecture/README.md) を参照してください。

### develop-guide/
開発規約とワークフローに関するガイドライン集です。

- **概要**: Git運用、コミット規約、ブランチ戦略、開発フロー、テスト戦略などを定義します。
- **注意**: 開発方針と規約を示すドキュメントであり、具体的なツール設定や実装詳細は掲載されていません。
- **主な内容**:
  - 開発ワークフロー（スプリント、Issue駆動開発）
  - ブランチ規約（Git Flow、命名規則）
  - コミット規約（メッセージフォーマット）
  - テスト戦略（単体/統合/E2Eテスト）
- **詳細**: [develop-guide/README.md](develop-guide/README.md) を参照してください。

### frontend/
フロントエンドの機能仕様と設計に関するドキュメント群です。

- **概要**: Webフロントエンドの画面構成、主要機能、非機能要件、UIコンポーネント仕様を定義します。
- **注意**: UI設計の方向性を示すドキュメントであり、具体的なコンポーネント実装や詳細なマークアップは掲載されていません。
- **主な内容**:
  - 機能仕様書（画面一覧、主要機能）
  - 非機能要件（パフォーマンス、アクセシビリティ、レスポンシブ対応）
- **詳細**: [frontend/README.md](frontend/README.md) を参照してください。

## 補足 / 運用

- ドキュメントは随時更新してください。変更がある場合は該当ドキュメントと関連ドキュメントを同時に更新してください。
- 新規メンバーが参加した際は、まず各ディレクトリの `README.md` を順番に読んでもらい、プロジェクト全体の理解を深めてください。
- ドキュメントの構造や命名規則に関する提案がある場合は、Issue を作成してチームで議論してください。
- 各ドキュメントには `last_updated` フィールドがあるため、更新時は必ず日付を更新してください。

### CORS 設定

- アプリケーションの CORS 設定は環境変数経由で管理されます。
- 主な環境変数 / 設定キー:
  - `CORS_ALLOW_ORIGINS`: 許可するオリジンのリスト（カンマ区切りで指定可能）。開発時のデフォルトは `http://localhost:3000`, `http://127.0.0.1:3000` です。
  - `CORS_ALLOW_CREDENTIALS`: クレデンシャルを許可するかどうか（`true`/`false`）。デフォルト: `true`。
  - `CORS_ALLOW_METHODS`: 許可する HTTP メソッド（デフォルトは `*`）。
  - `CORS_ALLOW_HEADERS`: 許可するヘッダ（デフォルトは `*`）。

本番環境ではワイルドカード（`*`）を用いたオリジン許可は推奨されません。必要なオリジンのみを列挙してください。
