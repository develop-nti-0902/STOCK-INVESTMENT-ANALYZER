## 概要

- **目的**
	- このフォルダはプロジェクトの開発規約とワークフローに関するガイドライン資料を集約します。Git運用、コミット規約、ブランチ戦略、開発フロー、テスト戦略などを確認するためのドキュメント群です。

- **利用方法**
	- 開発開始時、PR作成時、コードレビュー時に参照してください。まず `development-workflow.md` で全体の流れを把握し、各規約の詳細を必要に応じて確認してください。

## ファイル構成

### 主要ファイル
- [development-workflow.md](development-workflow.md) — プロジェクト全体の開発ワークフロー（スプリント、Issue駆動開発、開発フロー）。
- [README.md](README.md) — この案内ファイル。

### 規約・ガイドライン
以下は開発における具体的な規約とガイドラインです。各ファイルは対応する領域のルール、命名規則、ベストプラクティスを説明します。
- [BRANCH-REGULATION.md](BRANCH-REGULATION.md) — ブランチ戦略と命名規則（Git Flow準拠、feature/fix/hotfixなど）。
- [COMMIT-REGULATION.md](COMMIT-REGULATION.md) — コミットメッセージの規約（type、scope、フォーマット）。
- [testing_strategy.md](testing_strategy.md) — テスト戦略（単体/統合/E2Eテスト、カバレッジ目標、命名規則）。

## 補足 / 運用

- ドキュメントは随時更新してください。規約変更がある場合は変更箇所と理由を追記してください。
- 新規メンバーが参加した際は、まず `development-workflow.md` を読んでもらい、全体の流れを理解してもらってください。
- より詳細なアーキテクチャ設計やレイヤ構成については `docs/architecture/` を参照してください。
